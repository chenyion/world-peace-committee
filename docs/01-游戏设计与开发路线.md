## 1. 一句话介绍

玩家担任架空世界的和平委员会主席，在有限资源和任期内，通过外交、援助、议会与战略干预处理相互关联的国际危机，最终使世界危机值降到 0。

核心体验：**为解决一场冲突做出的决定，会改变其他国家的利益，并成为下一场事件的起因。**

玩家既可以直接介入 A、B 两国的争端，也可以先处理 C、D 两国的供应、联盟和政治诉求，间接改变 A、B 的选择。

## 2. 产品定位

| 项目 | 初版方案 |
| --- | --- |
| 类型 | 单机回合制策略、事件叙事、轻量世界模拟 |
| 主要操作 | 阅读局势、选择目标、投入资源、谈判、提案、投票 |
| 世界规模 | 7 国，2 个三国联盟，1 个中立国家 |
| 标准局目标 | 约 30～45 分钟，可随时存档续玩 |
| 标准任期 | 暂定最多 24 回合，允许提前获胜 |
| 单回合时间尺度 | 一个外交周期，不强制等于某个现实时间单位 |
| 画面 | 2D 架空地图、事件卡片、人物肖像、议会席位 |
| 屏幕 | 优先验证竖屏，地图可放大查看 |
| 重玩来源 | 国家诉求、局势组合、事件条件、决策历史 |
| 联网范围 | 核心模拟本地运行；发行相关服务按实际平台要求接入 |

### 2.1 三种主要乐趣

1. 判断：识别冲突背后的资源、安全和国内政治诉求。
2. 布局：先前的援助、调查和承诺，成为后来的谈判筹码。
3. 叙事：同一场争端可以走向合作、威慑、战争或联盟重组。

### 2.2 首版设计边界

- 国家与领导人有固定身份，保持玩家辨识度。
- 国家按利益和规则回应，不要求接入大模型。
- 军事冲突采用战略层面结算，不制作部队即时操控。
- 事件允许汇合，避免每个选项无限生成独立剧情树。
- 七国从首个完整可玩原型起共同存在；通过逐步开放操作降低教学负担。

## 3. 世界与主线结构

世界名为“伊澜”，七国共同构成初版可交互世界。地图之外的区域仅作背景，不作为隐藏第八国介入。

“长夜战争”结束后，七国签订《星湾宪章》，成立世界议会和世界和平委员会。议会制定共同规则，委员会负责调查、调解、援助与执行。玩家接任时，一场跨境水源争端正沿着粮食、能源、运输和联盟承诺扩散。

| 阶段 | 局势重点 | 玩家任务 |
| --- | --- | --- |
| 前期：取得信任 | 边境争端、信息不全、预算有限 | 调查原因，选择优先事项 |
| 中期：承担后果 | 贸易中断、联盟介入、承诺到期 | 处理连锁反应和资源挤兑 |
| 后期：建立秩序 | 停火执行、资源安排、履约监督 | 清除危机根源，实现归零 |

阶段由状态驱动。玩家能够提前解决问题，也可能因持续失误迅速进入全面危机。

## 4. 玩家权力与行动边界

玩家身份为世界和平委员会主席，拥有有限授权。

可直接决定：派遣调查团、发起调解、分配现有援助、安排委员会人员、提出议案。

需要外部配合：进入国家领土、执行制裁、部署维和、达成停火、获得额外拨款。

委员会没有独立无限军队。维和力量由成员国提供，受到授权、预算和供给限制。

“引导宣战”保留为高风险战略路线：玩家通过安全承诺、政治支持或干预授权，使某国更倾向采取军事行动。最终是否宣战仍由国家根据利益和风险决定。军事胜利不会直接清空危机，还会产生停火、伤亡救济、重建和关系修复问题。

## 5. 回合流程

1. **简报阶段**：展示新消息、既有危机期限、国家公开动作和待履行承诺。
2. **研判阶段**：免费查看地图、国家档案、事件关系和议会意向。
3. **行动阶段**：默认 3 点行动力，进行调查、外交、援助或提案等操作。
4. **回应阶段**：国家根据当前利益、关系和承诺回应。
5. **执行阶段**：处理协议执行、战争状态、贸易影响和到期后果。
6. **结算阶段**：计算危机值、资源、公信力，判定胜负并自动存档。
7. **下一回合准备**：若尚未结束，选择符合条件的新事件，生成简报。

胜负在抽取下一回合新事件前判定。重大风险必须已进入当前世界状态，不能为了制造难度临时补入隐藏危机阻止胜利。

阅读不消耗行动力；改变局势才消耗。涉及重大支出、不可撤销承诺或军事授权时提供明确确认。

## 6. 资源系统

| 资源 | 用途 | 来源 | 约束 |
| --- | --- | --- | --- |
| 行动力 | 控制本回合行动数量 | 每回合恢复至 3 | 默认不跨回合积累 |
| 预算 | 援助、调查、监督与维和 | 会费、专项拨款 | 长期项目有维护支出 |
| 外交影响力 | 邀请会谈、施压、争取支持 | 成功调解、兑现承诺 | 高强度外交消耗较多 |
| 公信力 | 决定委员会的可信程度与授权稳定性 | 公正调查、透明执行 | 偏袒、失信和丑闻会损害 |

首个剧本初始值暂定：预算 30、外交影响力 20、公信力 60/100、行动力 3。

基础会费暂定每回合 6 预算；拒缴和专项拨款应明确显示来源。具体行动费用在原型中统一配置，避免文案与实际扣费不一致。

预算不足不会立即判负。玩家可以缩减项目、寻求拨款、暂停支出或接受附带条件的支持；违约与项目中断会留下后果。

### 6.1 情报

- 已确认：公开条约、调查确认的事实。
- 可信推测：有来源的外交消息和顾问分析。
- 未经证实：传闻、单方指控、利益相关方提供的材料。

界面区分事实、推测与未知。隐藏动机应能通过调查、对话或行动模式逐渐发现。

## 7. 国家、关系与自主行为

国家核心属性包括经济能力、军事实力、国内稳定、资源依赖、对委员会的信任、领导层倾向。

国家之间记录关系、贸易依赖、安全承诺和历史恩怨。同盟关系不自动覆盖所有双边分歧。

初版国家决策使用规则与评分：

> 行动吸引力 = 经济收益 + 安全收益 + 国内支持 + 履约收益 − 财政成本 − 军事风险 − 外交损失。

领导人性格调整各项权重，并设置不能轻易跨越的底线。国家可以拒绝不符合利益的建议，也可以提出交换条件。

每回合只结算与当前局势有关的关键国家动作，避免七国同时刷出大量无关通知。

### 7.1 联盟

- **环海协作同盟**：岚原、澄海、丰谷。重视贸易、航运和经济互助，不自动共同参战。
- **大陆安全协约**：赤峰、灰岭、曜沙。重视边境安全与互助，但进攻行为不自动获得共同防御支持。
- **中立成员**：星湾。承担调解与清算职能，不保证始终支持委员会。

初版保留固定成员关系，以及支持、拒绝履约、暂停合作三种状态。正式动态加入、退盟和新建联盟留待后续扩展；危机剧情可触发有限的联盟裂痕状态。

## 8. 行动列表

| 行动 | 直接作用 | 主要风险或后续 |
| --- | --- | --- |
| 调查 | 确认事实，解锁证据和新方案 | 耗时、被拒绝进入、证据遭质疑 |
| 调解 | 推动会谈、撤军或临时停火 | 缺乏执行安排会复发 |
| 援助 | 缓解短缺与人道压力 | 运输受阻、挪用、依赖 |
| 拉拢 | 争取投票、合作与公开表态 | 需要让步和履约 |
| 制裁 | 提高对抗成本 | 民生受损、替代贸易、反制 |
| 安全保证 | 缓解受威胁国家的焦虑 | 对方冒险、保证被要求兑现 |
| 维和部署 | 降低升级风险，监督协议 | 授权、供给、经费持续消耗 |
| 战略施压 | 改变力量对比，增加谈判压力 | 误判、提前开战、联盟动员 |
| 制度建设 | 仲裁、资源共享、履约监督 | 前期成本高、需各国接受 |
| 暂不介入 | 保存资源、等待更多信息 | 按局势自然演化，可能错过窗口 |

“暂不介入”需要显示当前趋势和信息可信度，不默认等同于惩罚。部分争端会自行缓和，部分会升级。

## 9. 世界议会

七国各有一席、一票，委员会主持但没有额外国家票。首版无常任理事国与否决权。

| 议案类别 | 通过条件 |
| --- | --- |
| 普通议案：调查、援助协调、监督框架 | 至少 4 票赞成 |
| 重大议案：强制制裁、军事授权、宪章级改革 | 至少 5 票赞成 |

门槛以全部 7 席计算，弃权与缺席不降低所需赞成票。普通议案不自动赋予跨境强制执行权，需对象国同意的行动仍保留准入条件。

### 9.1 一项议案的构成

1. 目标：停火、开放航道、建立调查或共享机制。
2. 措施：援助、制裁、监督、维和。
3. 承担方式：谁出资、谁执行、持续多久。

流程：选择模板 → 修改条款 → 查看各国理由 → 游说与交换 → 投票 → 执行监督。

提交和表决合计暂耗 1 行动力，单独游说另计行动。首版每回合最多表决 1 项正式议案，防止无限试票。

表决通过只产生授权，实际效果取决于执行资金、成员履约和对象国反应。承诺记录在独立清单中，展示期限、成本与失信后果。

## 10. 事件系统与分支规则

### 10.1 三层事件

| 层级 | 功能 | 示例 |
| --- | --- | --- |
| 主线危机 | 构成本局主要矛盾 | 跨境水源、航道中断、联盟对峙 |
| 状态触发事件 | 回应世界状态和玩家行为 | 制裁后的短缺、失信后的拒缴 |
| 环境事件 | 改变局部条件 | 旱情、风暴、设备故障 |

### 10.2 事件模板字段

每个事件记录：唯一 ID、参与方、触发条件、互斥条件、冷却时间、阶段、期限、已知信息、可选行动、行动前置条件、立即效果、延迟效果、超时结果、后续事件和关闭条件。

事件模板与实例分离：模板可复用，实例保存本局参与方、选择、证据、计时与随机结果。

### 10.3 分支原则

- 有因才有果：没有边境部署就不触发边境误击。
- 状态可汇合：不同原因导致的粮食短缺，可以复用短缺处理机制。
- 来源要保留：旱灾、封锁、援助中断导致的短缺，其责任与选项不同。
- 重大恶化有窗口：关键危机升级前提供至少一次可行动的预警。
- 概率可理解：显示风险级别；掌握充分情报时可显示估计区间。
- 结果可追溯：结算指出主要诱因和相关历史决定。
- 不重复惩罚：同一底层危机的新闻、难民与封锁影响按规则去重，避免仅因显示多条消息就重复加分。
- 存档不重抽：随机种子及已确定结果随存档保留。

同一事件不要求每次产生不同结果。确定性的因果也很重要，多样性来自局势、利益、执行条件与有限随机性的组合。

## 11. 首个剧本：镜河之争

赤峰与丰谷围绕镜河下游供水发生争端。灰岭掌握上游水库，曜沙向赤峰提供能源，澄海掌握粮食外运航线，岚原需要稳定的粮食和能源进口，星湾主持跨国结算。

| 路线 | 处理方式 | 可能后果 |
| --- | --- | --- |
| 直接调解 | 邀请赤峰、丰谷停火谈判 | 很快降温，但水源问题可能仍未解决 |
| 上游调查 | 查明灰岭水库与旱情 | 找到真实原因，但需要准入与维修资金 |
| 供应谈判 | 与曜沙谈能源交付条件 | 提高动员成本，也可能影响民用能源 |
| 航运协调 | 争取澄海恢复粮食通道 | 稳定经济，但必须处理保险和检查争议 |
| 议会监督 | 推动流量监测、撤军和观察团 | 需要跨联盟支持、预算和准入 |
| 强硬施压 | 支持一方威慑或军事行动 | 可能迫使让步，也可能触发战争 |
| 处理旁支 | 先解决岚原供应或星湾信用风险 | 争取后续筹码，同时承担边境恶化风险 |

理想解决方案不预设为唯一答案。可通过工程合作、安全换供水、临时托管等不同安排解决；战争后也允许达成和平，但代价与待处理问题更大。

## 12. 危机值与胜负

危机值由世界状态计算，范围 0～100。所有危机贡献非负，不能以一处和平抵消另一处战争。

| 来源 | 示例 | 消除方式 |
| --- | --- | --- |
| 冲突 | 战争、封锁、严重对峙 | 停火、撤军、解除封锁 |
| 人道与经济危机 | 严重短缺、难民失所 | 恢复供应、救援、安置 |
| 升级压力 | 动员、连锁参战风险 | 解除动员、澄清承诺、安全协议 |
| 协议失效风险 | 违约、缺少必要监督 | 履约、建立执行保障 |

首个剧本开局危机值暂定 **46**：边境对峙 16、供水与粮食短缺 12、联盟动员风险 10、航运与履约风险 8。

实现时，每个计分来源有唯一 ID、类别、强度、关联事件与关闭条件。新闻事件只改变来源状态，不独立叠加重复分数。

### 12.1 胜负规则

- 回合结算后危机值为 0，立即获胜。
- 危机值达到 100，触发全面失控失败。
- 公信力低于 15 且连续维持 3 次结算，触发委员会解散；首次跌破时明确警告，并开放补救措施。
- 最后一个任期回合先检查危机归零，再判定任期结束。未归零则未达成目标，但保留评级与复盘。
- 危机归零不要求所有国家互相喜欢，也不要求消除所有普通分歧。

### 12.2 确保归零可以实现

标准模式限制独立重大危机的生成预算。后期以处理已有危机及其因果后续为主，不无限新增无关大战。

暂时停火若缺少关键执行条件，会留下可见的协议风险来源；真正解决根源后，该来源关闭。不能把不可见、永不消失的“仇恨值”当作通关门槛。

胜利评级考虑伤亡、公信力、失信次数、资源使用和长期保障，生成“协商秩序”“共同繁荣”“强制维稳”等不同结局描述。

## 13. 重玩与局外进度

初版七国身份固定，初始状态、危机组合、领导人的本局优先诉求和部分事件参数可变化。教学局使用固定种子与可解释事件顺序。

局外解锁以新剧本、档案、顾问工作方式和挑战条件为主，不提供永久预算碾压。

后续可扩展：其他地区剧本、完整动态联盟、国内派系、委员会制度改革、无尽模式。无尽模式独立说明其持续模拟目标，不沿用标准局的归零即结束规则。

## 14. 手机界面与美术方向

主入口：世界、事件、议会、委员会。

- 顶部：危机值、回合、资源。
- 世界：七国地图、边界、主要河流和运输关系。
- 事件：摘要、相关国家、期限、证据与选项。
- 议会：七席态度、议案条款、游说承诺。
- 委员会：预算、项目、顾问、历史记录。

国家使用固定名称、旗帜、配色和领导人肖像。颜色之外还用形状与文字区分，避免仅靠红绿判断状态。

事件默认显示简短摘要，详细背景折叠。每个选项显示费用、确定收益、风险与已知延迟后果。失效选项显示原因和解锁方式。

建议美术：架空政治地图、印刷档案与半写实插画人物。地图强调可读性，重要连线按需展示；战争以地图状态与报告表达。

每次已确认行动后保存，回合结算保存完整检查点。切后台恢复时展示当前阶段，防止重复扣费和重复执行效果。

## 15. 首版内容范围

| 内容 | 首个可玩原型 | 公开测试目标 |
| --- | --- | --- |
| 国家 | 固定 7 国 | 固定 7 国 |
| 联盟 | 两个三国联盟与一个中立国 | 增加履约、拒绝、暂停合作状态 |
| 主线 | 镜河之争 | 3 条可组合主线危机 |
| 事件 | 16 个 P0 模板及其阶段 | 32 个 P0＋P1 模板；另有 8 个储备设计 |
| 国家决策 | 利益、信任、底线 | 加入领导倾向与承诺权重 |
| 议会 | 提案、游说、七国投票 | 完整执行与失信后果 |

“模板”是一种独立事件逻辑，不将换国名或改一句文案算成新事件。内容量可以缩减，但七国开局保持不变。

## 16. 开发路线

以一名熟练全职开发者、有基础美术支持为参考，估算如下；兼职、首次移动端开发及复杂平台接入会增加工期。

| 阶段 | 参考时间 | 交付物 | 通过标准 |
| --- | --- | --- | --- |
| 规则与纸面推演 | 1～2 周 | 七国关系、行动表、危机来源、事件流程 | 能推演出多种胜利和失败路线 |
| 七国核心原型 | 3～4 周 | 完整回合、国家回应、议会、镜河主线 | 直接调解与处理第三国能产生不同结果 |
| 手机体验样片 | 3～4 周 | 地图、卡片、肖像占位、存档、真机包 | 无讲解也能理解主要行动与代价 |
| 内容与系统扩充 | 4～6 周 | 事件库、项目执行、联盟履约、结局 | 连锁事件可追溯，无明显万能策略 |
| 内部测试与平衡 | 3～4 周 | 随机种子回归、数值修正、教学完善 | 排除无解死锁、无限循环、存档损坏 |
| 平台测试准备 | 2～4 周 | SDK 验证、发布素材、测试包与资料 | 达到选定测试形式的提交条件 |

合计约 **16～24 周**研发时间，不包含外部资质办理及审核等待。平台要求与 SDK 验证应在早期并行调查，不能等到最后阶段才发现引擎接入障碍。

### 16.1 第一阶段具体工作

1. 固定七国 ID、地图位置、联盟和资源关系。
2. 完成镜河危机的真实原因、公开信息与隐藏信息。
3. 配置 8～10 种基础行动及其费用。
4. 让七国能对调查、援助、停火和议案作出可解释回应。
5. 接通“简报—行动—国家回应—危机结算—存档”。
6. 手动验证直接调解、上游合作、供应施压三种路线。
7. 确认七国投票门槛、危机归零和失败判定。

## 17. 技术与内容生产

采用 2D 引擎与数据驱动规则。若没有既有引擎经验，可用 Godot 做安卓导出和 UI 验证；选型前单独验证所需平台 SDK。官方资料见文末，具体版本与插件兼容性在实施时确认。

| 模块 | 职责 |
| --- | --- |
| 世界状态 | 国家、关系、联盟、资源、危机来源 |
| 回合系统 | 固定执行顺序、延迟任务、胜负判定 |
| 事件系统 | 条件筛选、阶段推进、分支和关闭 |
| 国家决策 | 利益评分、底线、回应解释 |
| 议会系统 | 议案、游说、投票、执行项目 |
| 存档与复盘 | 随机状态、行动日志、历史因果、版本迁移 |
| 界面 | 地图、事件、档案、议会和提示 |

数据至少包含国家表、领导人表、关系表、联盟条款表、行动表、事件模板表、议案表与本地化文本表。国家与人物显示名不作为逻辑主键。

优先制作两个内部工具：

- 事件检查器：检查不存在的 ID、断链、互斥冲突、无法关闭的事件和错误计分来源。
- 模拟运行器：用固定策略与多个种子检查状态越界、重复效果、回合死锁和存档回放一致性。

自动模拟能发现规则错误，不能代替真人判断策略是否有趣。

## 18. 验证重点

- 至少三种有差异的有效解法，避免每局重复唯一最优操作。
- 玩家能说明危机值为什么升降。
- 第三国行动能实际影响主线，而非仅改变关系数字。
- 各国拒绝有理由，底线与人物设定一致。
- 已知风险与实际后果匹配，重大随机恶化有预警。
- 七国投票不会因弃权错误降低门槛。
- 已完成的危机不会无条件复发。
- 危机归零、最后回合胜利、委员会解散等边界正确。
- 移动端中断、恢复与版本更新不丢失已确认行动。

先邀请小规模玩家观察其理解和决策过程，再扩大发行测试。测试指标围绕教学完成、退出位置、选择分布、失败原因与再次开局意愿设置，不提前虚构行业标准。

## 19. TapTap 发布与商业化

建议路线：核心原型 → 手机样片 → 准备预约素材 → 小规模测试 → 修正玩法 → 扩大测试 → 满足对应条件后发布。

根据本轮规划参考的 TapTap 官方文档，预约期间不强制上传 APK；测试和正式发布有各自的版本、资质与审核流程。文档区分“正式上线”和“正式上线 试玩版”。实际选择需结合发行地区、联网及收费形态，在提交前重新核对。

提前确定包名、开发者主体、收费方式、联网范围和适用资质。预留隐私政策、实名及防沉迷等适用工作。本文不据此承诺任何发布形态必然获批。

商业化优先考虑买断，或体验首个剧本后解锁完整内容；后续增加独立剧本。测试阶段先验证玩法。不售卖危机下降、议会票数或额外行动力。
